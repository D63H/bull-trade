# Monitoring, briefs and watches

Monitoring is read-only. A watch may fetch, compute, save and alert. It may never send an order. If a watch condition implies action ("stop got hit, re-enter"), the alert opens a proposal; the lifecycle does the rest.

## Grok Bot routines

Each Bot can own routines (schedules or event triggers). Ask the owning Bot to create one with: schedule and time zone, input source, expected result, approval boundary. Keep routines few and specific; the app keeps only recent run records, so a routine that produces something durable should also write to `/workspace/trading-desk`.

Recommended starting set (the user picks; none is on by default):

| Routine | Owner | Schedule | Output |
| --- | --- | --- | --- |
| Desk brief | Desk Lead | weekdays before the open (e.g. 09:00 ET) | `briefs/YYYY-MM-DD-desk.md` and a short post |
| Book check | Risk Manager | 10:00 and 15:30 ET while positions are open | alert only if something changed or a limit is near |
| Crypto weekend check | Market Analyst | Sat/Sun once daily, only if crypto positions exist | snapshot post |
| Earnings/calendar refresh | Research Analyst | weekly | `research/calendar.md` |
| Watch heartbeat check | Desk Lead | hourly while watches run | restart dead watches, journal gaps |
| Weekly review | Trade Reviewer | weekly | review posted by DM |

## The desk brief

Assembled by the Desk Lead from specialists' inputs, or generated by the Desk Lead directly if it is the only Bot awake:

```
DESK BRIEF | 2026-08-26 13:00 UTC (09:00 ET) | paper (uat), data delayed ~15m | account <id>
markets (Market Analyst, stock-snapshot 12:58 UTC):
  SPY 648.10 (+0.3% premkt) | QQQ 572.4 (+0.4%) | AAPL 231.2 (+0.5%)
  BTCUSD 98,420 (-0.8% 24h, crypto-snapshot, real-time)
book (Risk Manager, state cache 12:59 UTC): 1 position, AAPL long 8 @ 230.00, uPnL +$9.60,
  stop 224.00 working (verified in open orders); open risk 0.5%; day PnL 0.0%; settled cash n/a (margin)
research (Research Analyst): NVDA earnings 2026-08-27 after close [source]; nothing breaking on held names
open items: BD-20260825-01 live; no pending tickets
```

Facts with sources, environment and freshness; interpretation, if any, on one clearly labelled line. No trade suggestions.

## Watches

A watch is a condition plus an alert, implemented per `webull-streaming` (supervised scripts with heartbeats under `/workspace/trading-desk/watch/`). Data budgets: market-data endpoints 60/60s each; account state through the state cache only.

| Watch | Data | Alert to |
| --- | --- | --- |
| Price crosses a level | snapshot poll (15-60s) or MQTT | user, Desk Lead |
| Order filled, cancelled or rejected | trade events + `detail` polling | Execution Trader, Trade Reviewer |
| Position without working protection | state cache: positions vs open orders | Risk Manager, Desk Lead (incident) |
| Daily loss stop approached (80%) or hit | state cache vs start-of-day equity | user, Risk Manager |
| Halt / no prints on a held name during CORE | snapshot anomalies | user, Desk Lead |
| Earnings within 2 sessions on a held name | calendar + positions | user, Risk Manager |
| Option expiry within 5 sessions / futures roll date | positions + instrument facts | user, Risk Manager |
| Broker unreachable or 429s for more than N minutes | any endpoint failing | Desk Lead |

An alert message carries: what fired, the value and the threshold, the source, environment and UTC time, and the proposal id if related. Alerts do not include instructions to trade.

## Market-hours awareness

Equities monitoring runs where the risk is: CORE plus the first and last half hours of extended hours. Overnight equity watches only when the user asks. Futures watch near-24x6; crypto 24/7 with UTC day boundaries for the loss stop. A watch that fires on delayed sandbox data says so in the alert.

## Hygiene

- Every watch logs to `/workspace/trading-desk/watch/<name>.log` with UTC timestamps and touches a heartbeat.
- A watch that fails silently is worse than none: the heartbeat routine restarts it and journals the gap.
- Do not run more than a few watches at once; each is a process on the shared computer, and MQTT allows one desk connection by desk rule.
- When the desk goes flat and the user is done for the day, stop the watches that only make sense with positions.

## Never

- Never let a watch place, replace or cancel an order. Even a "protective" one. It alerts; the desk acts through a ticket.
- Never alert with unsourced numbers or without the environment line.
- Never poll faster than the desk needs; a rate-limited desk is a blind desk, and repeated 429s can escalate to an IP block.
